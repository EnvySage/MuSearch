# 术语表

> **规则**:每遇到一个新名词,用**大白话**记一遍,附一个**例子**。
> 面试前翻这个文件就是复习——它比背定义有用,因为是**你自己用自己的话写的**。

---

## StateGraph(状态图)

**大白话**:一张流程图。你定义几个"盒子"(节点),用箭头连起来,告诉 LangGraph 数据怎么流。

**例子**:流水线——原料从左边进,经过几个工位,成品从右边出。每个工位只能拿到"当前状态"。

**注意**:它是个**类**。要先 `StateGraph(你的状态类型)`,再加盒子,最后 `compile()` 才变成能跑的东西。

---

## State(状态)

**大白话**:一个**共享的笔记本**。所有节点都能读,也可以往上写。

**例子**:接力赛的接力棒。每个节点跑完把自己那份结果写进去,下一个接着用。

**关键**:写进去默认不是"覆盖"而是"合并"——怎么合并见下面 Reducer。

---

## Reducer(合并规则)

**大白话**:两个节点都要往**同一个字段**写东西时,按什么规则合。

**例子**:
- 不写 reducer(默认)= **覆盖**。后写的把先写的顶掉,像白板擦掉重写。
- `Annotated[list, operator.add]` = **追加**。像往清单后面接着加,谁都不丢。

**要分清两种情况**:
- 同一条执行路径上先后写同一字段,没 reducer 时后一次会覆盖前一次。
- `Send` 并行扇出时,多个任务在同一轮写同一字段,没 reducer 时 LangGraph 不知道如何合并,会报并发更新冲突。

`operator.add` 用在列表上就是列表拼接:`["A"] + ["B"]` → `["A", "B"]`。每个并行研究员返回一份列表,主图 reducer 把这些列表合起来。

**在哪见过**:`state.py:68`

## Node(节点)

**大白话**:一个**普通函数**。输入当前状态,输出要更新的字段。

**例子**:
```python
def 我的节点(state):
    return {"结果": "算完了"}
```
就这么简单——没有继承,没有特殊基类。

---

## Edge(边)

**大白话**:箭头。决定**上一个节点跑完去哪个节点**。

**例子**:`g.add_edge("搜完", "总结")` —— 搜完就去总结。

两个特殊的:`START`(从哪开始)、`END`(到哪结束)。

---

## ReAct 循环

**大白话**:让模型**反复"想一步 → 做一步"**的循环。ReAct = Reason + Act。

**例子**:你让助手查资料——
1. 搜一次,看到结果
2. 判断"还不够",再搜
3. 觉得够了,停下给答案

**骨架**:`模型节点 ⇄ 工具节点` 两个盒子来回跑,直到满足条件跳出。

**为什么重要**:这是**所有 agent 的本质**。学 LangGraph,核心就是学这个循环。

**最大的坑**:怎么保证它**一定会停**。必须有出口条件(迭代上限 / 模型主动说"完了"),否则死循环烧钱。

---

## Tool(工具)

**大白话**:给模型的**函数**。模型不能直接执行代码,它只能"请求调用某个工具",由你的程序去执行。

**例子**:你给它一个 `search(关键词)`。模型输出"我要调 search,参数是 LangGraph",你的程序跑完,把结果塞回去。

**关键**:模型能做的一切 = 你注册的工具列表。**没给工具的事,它做不了。**

**在哪见过**:`utils.py:220` 的 `think_tool`——注意它**函数体是空的**,纯粹是为了让模型"把反思写出来"。

---

## Command(路由指令)

**大白话**:节点返回的东西,一次说清两件事——**状态怎么更新** + **下一步去哪**。

**例子**:
```python
return Command(goto="下一步", update={"字段": 值})
```

**对比老写法**:老办法用单独的"边函数"决定去哪,状态和路由是分开的。`Command` 把两件事收进一个返回值。

**它更新哪张 state 白板**:`update` 更新的是**当前执行这个节点的那张图**的 state。`0.3demo.py` 里 `supervisor` 属于主图,所以 `update={"topics": topics}` 把完整题目清单写入主图的 `State`;它不会自动把 `topics` 填进每个研究员子图。

**和 `Send` 的分工**:
- `goto` 决定派谁、下一步去哪。`goto=[Send("researcher", {...}), ...]` 会按每个子问题创建研究员任务,每个 `Send` 字典是对应子图的输入。
- `update` 记录当前图的 state 更新。例子里的 `topics` 只是主图保存的完整计划,研究员实际收到的是 `Send` 里单独传入的 `topic`。
- 这份 demo 后续没有节点读取主图的 `topics`,所以当前它用于检查/返回计划;删掉这个 `update` 不影响研究员派发和最终报告,只是最终 state 不再保留完整计划。

**在哪见过**:`deep_researcher.py:217-223`

## Subgraph(子图)

**大白话**:**把一张图当成另一张图的一个节点**。像函数调用。

**例子**:`deep_researcher` 里,"研究员"本身就是一张完整的图——有模型节点、工具节点、压缩节点。主管图把整张"研究员图"当成一个盒子用。

**两种用法**:
- 当节点:`add_node("研究员", 研究员子图)`
- 手动调用:`研究员子图.ainvoke(...)` —— 适合并行

**在哪见过**:`deep_researcher.py:353-363`、`710`

## 并行 Fan-out

**大白话**:一次派出去**好几个任务同时干**,不是排队一个一个来。

**两种做法**:
- `asyncio.gather` —— 自己手动并发,好控制并发数
- `Send()` —— LangGraph 的动态派发机制,框架帮你调度。运行配置可以设置 `max_concurrency`;要比较它和 `gather` 的实际并发峰值、成本和控制粒度,还得做运行实验。

**在 0.3demo.py 里的用法**:主管用 `Send` 把每个 `topic` 交给一个研究员子图;子图 state 和主图 state 各有作用域。子图返回的 `findings` 是列表,主图的 `findings: Annotated[list, operator.add]` 把并行结果合并。

**注意**:单个研究员子图里目前只有 `compress` 写一次 `findings`,因此子图字段加 reducer 不是“用了 Send 就必需”;它的列表形状要和返回值、父图字段对齐。主图 reducer 则是并行研究员共同回写主图 `findings` 时所需的合并规则。

**在哪见过**:`deep_researcher.py:295-305`(asyncio)/ `legacy/graph.py:181`(Send)

## checkpointer / interrupt

**大白话**:
- **checkpointer** = 存档。图跑到一半存到磁盘,断电也能接着跑。
- **interrupt** = 暂停球赛,等人回话。

**例子**:图跑到"要不要继续?"时调 `interrupt("继续吗")`,整张图**暂停并存档**;你回复后从断点继续。

**为什么必须配对**:没有存档的 interrupt 没意义——人还没回话,进程已经没了。

**在哪见过**:`legacy/graph.py:142-192`(上游现版本删掉了这个能力)

## MCP

**大白话**:一个**插件插座**。让 agent 接上它天生没有的能力。

**例子**:agent 自带只有搜索。你插一个 arxiv 的 MCP,它就多了"查论文"的能力。上游仓库的 `arxiv.md` / `pubmed.md` 就是这么跑出来的。

## RAG

**大白话**:先把资料**切块 + 建索引**,提问时只抽出"最相关的几块"喂给模型。

**例子**:像书后面的索引。你不把整本书读一遍,而是查到页码,**只翻那几页**。

**和"全塞给模型"的区别**:
- 资料少(几十个网页)→ 全塞,让模型自己读。**更准**,因为不会漏。
- 资料多(几百万文档)→ 必须 RAG,塞不下。

**注意**:上游仓库**把 RAG 删掉了**(老版本有)。见 `IMPROVEMENTS.md`。

## 结构化输出(Structured Output)

**大白话**:强制模型**按你给的格式**返回,不许自由发挥。

**例子**:你声明"研究大纲是个字符串字段",模型就只能返回这个形状,不能返回一段散文。

**为什么需要**:下游代码要解析它的输出,格式一乱,后面全崩。

**在哪见过**:`deep_researcher.py:89-94`

## TypedDict

**大白话**:给普通字典加"字段说明"的工具。**它只是标注,不做检查。**

**例子**:
```python
class State(TypedDict):
    question: str
```
意思不是"这里必须是 str",而是"我**打算**放个 str"。你真塞个数字进去,**运行时不报错**。

**为什么用它**:LangGraph 要先知道 state 有哪些键,才能决定怎么合并。标注是给人、IDE 和 LangGraph 看的。

**注意**:跟 Pydantic 的 `BaseModel` 不是一回事——`BaseModel` **真的会校验**,`TypedDict` 不会。

## compile(编译)

**大白话**:把"图纸"变成"能跑的机器"。

**例子**:你加完节点、连完边,那张图**还只是描述**。`app = graph.compile()` 之后才能 `app.invoke()`。

**为什么单独一步**:有些东西只能在编译时定——比如要不要持久化(checkpointer)。所以它是一道"施工"工序,不是多余的仪式。

---

## invoke(调用)

**大白话**:开动机器,跑一次。

**例子**:`app.invoke({"question": "什么是 LangGraph"})` —— 传**初始状态**进去,等它跑完,拿回**最终状态**。

**两个注意**:
- 传进去的 dict **不必包含所有字段**。没传的键就"还不存在"
- 节点里读一个不存在的键会 **KeyError**。所以 `make_points` 里读 `state['question']` 能成(你传了),但如果它读 `state['answer']` 就崩(那时还没人写)

**补充(2026-10-14)**:判断"某栏要不要传初始值"——
- **有节点会写它** → 初始值可选(但传了是**安全网**:万一那条路没走,读它的人不会 KeyError)
- **只读不写**(如 `question`)→ **必须传**

## state 是白板,不是历史(2026-10-14 修正)

**我原来的误解**:state 像"过去的状态记录"。

**修正**:state 是一块**共享白板**。

- `messages` 那栏标了 `Annotated[list, operator.add]` → **追加**,看起来像流水账
- 但那是**一栏的合并规则**,不是 state 的本质
- `question: str` 那栏就是**一直贴着的便签**,谁进门都能读

**推论(最重要的一条)**:

> **指令跟着节点走(局部生效);要求跟着 state 走(谁需要谁读)。**

**为什么**:LangGraph 里**没有"整张图的 system prompt"**。每个节点是普通函数,各自拼各自的 messages。
跨节点的要求必须 ①摆上白板 ②目标节点主动读出来 —— **缺②等于没写**。

## 消息角色与"配对契约"(2026-10-14)

**四种角色的分工**:

| 角色 | 大白话 | 例子 |
|---|---|---|
| `SystemMessage` | **岗位说明**(你是谁、规矩) | "你是研究主管,拆成 2-4 个子问题" |
| `HumanMessage` | **递进来的工单**(具体材料) | 用户问的那句话 |
| `AIMessage` | 模型的回复 | 可以是正文,也可以是 `tool_calls` |
| `ToolMessage` | 工具的返回值 | `search` 搜回来的资料 |

**★ 配对契约(会踩)**:

> **`ToolMessage` 必须紧跟一条带 `tool_calls` 的 `AIMessage`,`tool_call_id` 要对上。**

**为什么重要**:想把"工具调用的历史"从上下文里摘掉(避免模型模仿着继续调工具,即 DSML 泄漏)时——

- 保留 `AI` + `Tool` 配对 → 那段"示范"还在 → 模型会模仿
- 只留 `Tool`、丢掉 `AI` → **变成孤儿** → 内容被**静默丢弃**(实测:一个 token 都没发出去)

**两条路都不通。唯一出路**:**把工具正文降级成纯文本,重包成一条 `HumanMessage`。**

**顺带**:`SystemMessage` 在某些链路(如本地代理)会被**静默替换**——写进去也可能到不了模型。

## BaseModel / Pydantic(2026-10-14)

**大白话**:**会自己检查自己的类**。你只写字段名和类型,它自动帮你:收参数、转类型、查错误、导 JSON、生成 schema。

**关键机制**:`class X(BaseModel)` 的**元类**(`ModelMetaclass`)在创建类时**扫描你的注解**,存成一张表:

```
你写的类体 → model_fields → model_json_schema() → 发给模型的工具定义
```

| 你写 | 机器翻译成 |
|---|---|
| `topics:` | `properties` 的 key |
| `list[str]` | `{"type":"array","items":{"type":"string"}}` |
| `= 默认值` | 从 `required` 里消失 |
| `Field(description="...")` | `"description"`(**模型看得到,又是一条提示词**) |

**三条必须记住**:
1. `= 默认值` 决定"必填还是选填",也决定 schema 的 `required`
2. 类型是**宽容转换**:`"20"` → `20`;转不了才报错
3. `Field` 的参数**一进两处**:schema(模型看)+ 校验器(代码查)

**和 `TypedDict` 的分工**:

| | `TypedDict` | `BaseModel` |
|---|---|---|
| 传错类型 | 静默通过 | 强行转换或报错 |
| 少字段 | 取用时才 KeyError | 构造即报错 |
| 拼错字段名 | 白送一个多余键 | 直接拒绝 |
| 用途 | 描述 state 形状(轻量) | 接模型输出、保证下游数据形状 |

**一句话**:`TypedDict` 是**标注**,`BaseModel` 是**契约**。

## 配置的三种通道(2026-10-14)

**问题**:节点函数要的东西(模型、key、工具、子问题)从哪来?

**三条通道,各管一类**:

| 通道 | 放什么 | 例子 |
|---|---|---|
| **state** | 每次运行**会变**的数据 | `topic`(每个研究员不同)、`messages`、`findings` |
| **模块级全局** | 每次都**一样**的配置 | `model`、`api_key`、`tools`、`MAX_ROUNDS` |
| **config**(v0.4 学) | 想**运行时改、不改代码**的配置 | 模型名、`max_tokens`、key |

**实测**:往子图 `invoke` 里多塞一个 `api_key` → **没人读,白传**(节点函数从全局抓,不从 state 取)。

**为什么要有第三条(v0.4)**:全局写死有三个后果——
① 所有角色被迫共用同一个模型 ② 换模型要改代码 ③ key 在代码里裸奔。
`config_schema` / `Configuration` 就是来解这个的。

## 结构化输出会静默失败(2026-10-14)

`with_structured_output(Plan)` 背后是 **tool calling**(LangChain 把类转成工具并强制调用)。

**但实测撞到**:模型把整个数组**序列化成了一个字符串**(`'["a","b"]'`)→ `parsed` 返回 **`None`**。

**后果**:`plan.topics` → `AttributeError: 'NoneType' has no attribute 'topics'`。

**对策**:

```python
plan = model.with_structured_output(Plan).invoke([...])
if plan is None:                      # ← 必须判空
    return {"topics": [state["question"]]}   # 降级
```

**记住**:它把成功率从 1/3 拉到接近 100%,**但不是 100%**。**吃它输出的代码都要判空。**

## asyncio.gather / ainvoke(2026-10-14)

**大白话**:让好几件事**同时跑**,而不是一件一件排队。

**三个改动**(串行 → 并行):

```python
# 串行
res = researcher.invoke({...})          # 同步,卡住等结果
for t in topics: ...

# 并行
res = await researcher.ainvoke({...})   # 异步,await 时交出控制权
outs = await asyncio.gather(*[...])     # 一起发出去,等全部完成
```

**注意**:
- 图里有异步节点,外层也必须异步:`async def main()` + `await app.ainvoke(...)` + `asyncio.run(main())`
- `gather` 的返回**顺序有保证**(`outs[0]` 对应第 1 个),不会串位
- **日志交错**就是并行在跑的证据(串行时打印是整齐的 1→2→3)
- **`gather` 控不住并发数**——上游为此特意不用官方 `Send`。见 `IMPROVEMENTS.md` 第 3 条
